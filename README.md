> 기본 운영 기간은 10주입니다. 11~12주차 계획은 스터디 연장이 결정되면 이어서 진행합니다.

## 진행 방식

한 주 동안 개인 브랜치와 하나의 PR을 계속 사용합니다.

1. 주차가 시작되면 `main`에서 `week{주차}/{이니셜}` 브랜치를 생성합니다.
2. 첫 문제를 푼 날 Draft PR을 생성합니다.
3. 매일 해결한 문제를 커밋하고 같은 브랜치에 push합니다.
4. 주간 문제를 모두 제출한 뒤 PR을 **Ready for review**로 전환합니다.
5. 스터디장이 마지막 날 제출 내역을 확인한 뒤 PR을 일괄 merge합니다.

```text
main
 └─ week01/jh  ── Draft PR 생성 ── 매일 풀이 커밋 ── Ready for review ── merge
```

세부 브랜치·커밋·PR 규칙은 [.github/CONTRIBUTING.md](.github/CONTRIBUTING.md)를 확인합니다.

`main` 브랜치는 직접 push하지 않고 PR로만 변경합니다. 원격 저장소 생성 후 [.github/BRANCH_PROTECTION.md](.github/BRANCH_PROTECTION.md)에 따라 강제 푸시와 브랜치 삭제를 차단합니다.

## 폴더 구조

이 저장소는 **주차별 → 참여자별** 구조를 사용합니다.

```text
.
├── week01/
│   ├── JH/
│   │   ├── algorithm/
│   │   │   ├── 신규_아이디_추천/
│   │   │   │   └── Solution.java
│   │   └── sql/
│   │       └── 조건에_맞는_회원수_구하기.sql
│   ├── SH/
│   │   ├── algorithm/
│   │   └── sql/
│   ├── YK/
│   │   ├── algorithm/
│   │   │   └── 숫자_문자열과_영단어/
│   │   │       └── solution.py
│   │   └── sql/
│   └── JY/
│       ├── algorithm/
│       └── sql/
├── week02/
└── ...
```

주차 단위로 PR을 만들고 검토하므로, 같은 주차의 제출 현황과 다양한 풀이를 한곳에서 비교하기 쉽습니다. 참여자 폴더명은 처음 정한 이니셜을 모든 주차에서 동일하게 사용합니다.

### 파일 작성 권장사항

- 알고리즘: `week{주차}/{이니셜}/algorithm/{문제명}/Solution.{확장자}`
- SQL: `week{주차}/{이니셜}/sql/{문제명}.sql`
- 문제명에는 공백 대신 `_`를 사용합니다.
- 추가 설명이 필요하면 문제 폴더에 `README.md`를 작성합니다.
- 다른 사람의 폴더는 수정하지 않습니다.
- Java 사용자는 [`templates/java/Solution.java`](templates/java/Solution.java), Python 사용자는 [`templates/python/solution.py`](templates/python/solution.py)를 문제 폴더에 복사해 사용합니다.
- SQL 풀이에는 [`templates/sql/solution.sql`](templates/sql/solution.sql)을 사용할 수 있습니다.
- 템플릿의 주석은 풀이에 필요한 항목만 남기고 작성해도 됩니다.

## 운영 규칙

### 가입비 및 반환

- 가입비는 **50,000원**입니다.
- 스터디 종료 후 누적 차감액을 제외한 잔액을 반환합니다.
- 누적 차감액이 50,000원에 도달하면 스터디에서 방출할 수 있습니다.

### 지각·미제출 기준

| 주간 제출 상태  |             차감액 |
| --------------- | -----------------: |
| 지각 1회        | 없음 (주 1회 패스) |
| 지각 2회 이상   |           10,000원 |
| 미제출 1회      |           10,000원 |
| 미제출 2회 이상 |           20,000원 |

- 공휴일과 프로젝트 집중 기간은 구성원 합의 후 제출 일정을 미루거나 차감 대상에서 제외할 수 있습니다.
- 지각과 미제출이 같은 주에 함께 발생한 경우의 계산 방식은 첫 모임에서 확정합니다.
- `지각`과 `미제출`을 구분하는 마감 시점도 첫 모임에서 명확히 정합니다.
- 벌금 액수와 운영 방식은 실제 진행 상황에 따라 구성원 합의로 조정할 수 있습니다.

### 오프라인 미팅

- 주 1회 모의 코딩 테스트 또는 풀이 피드백을 진행합니다.
- 기본 후보 요일은 **목요일**이며, 구성원 일정에 따라 변경할 수 있습니다.
- 공휴일·프로젝트 기간의 진행 여부는 해당 주 시작 전에 합의합니다.
